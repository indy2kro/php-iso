# Fixtures

Small ISO images used by the tests. The older images (`test.iso`, `subdir.iso`, ...) were created by hand; the images
below are generated by `build-fixtures.sh` in Docker (`debian:stable-slim`, privileged for the UDF loop mount) with
external tools: `xorriso`, `genisoimage`, `mkudffs` with the Linux UDF driver, and `pycdlib`.

Run `fixtures/build-fixtures.sh [image...]` to regenerate them (`--inside` runs the build directly on a host that
already has the tools). Rebuilding changes the image dates, so rebuild only what you need and then run
`UPDATE=1 tests/smoke/run.sh`. `MANIFESTS_ONLY="image..."` refreshes manifests without replacing the images.

| File | Purpose | Tool |
|------|---------|------|
| `rockridge.iso` | Rock Ridge (PX/TF/NM/SL), a symlink, a 214 character file name whose SUSP entries overflow the directory record (CE continuation area), a 5 level deep directory tree | `xorriso -as mkisofs -R` |
| `iso1999.iso` | ISO 9660:1999 Enhanced Volume Descriptor (type 2, version 2) without Joliet, long mixed case names | `genisoimage -iso-level 4` |
| `joliet_cjk.iso` | Joliet with Chinese/Japanese volume id, directory and file names | `genisoimage -J -joliet-long` |
| `no_extension.iso` | Plain ISO 9660 level 1, files without an extension (`README`, `LICENSE`) | `genisoimage -iso-level 1` |
| `rr_joliet.iso` | Rock Ridge + Joliet: 300 files in one directory (several sectors), empty file and directory, 70 KB binary file, 10 level deep tree, names with spaces, symbols, accents and a leading dot, a symlink | `xorriso -as mkisofs -R -J -joliet-long` |
| `rr_relocated.iso` | Rock Ridge directories deeper than 8 levels, relocated to `rr_moved` (CL / RE / PL) | `genisoimage -R` |
| `eltorito.iso` | El Torito catalog with a BIOS no emulation entry (4 virtual sectors) and an EFI entry in a second section | `xorriso -as mkisofs -b ... -eltorito-alt-boot -e ...` |
| `udf201.iso` | Pure UDF 2.01 (no ISO 9660), written by the Linux kernel UDF driver; same tree as `rr_joliet.iso` | `mkudffs --udfrev=0x0201` + loop mount |
| `udf_bridge.iso` | UDF 1.02 bridge with Joliet and Rock Ridge, the same content in three trees | `genisoimage -udf -J -R` |
| `pycdlib_udf260.iso` | UDF 2.60 + Joliet + Rock Ridge written by an independent implementation (ISO names are `F00001.;1`, real names in the other trees); same tree as `rr_joliet.iso` | `pycdlib` |

A real UDF 2.50+ image with a metadata partition could not be produced with these tools (`mkudffs` only writes 2.50
for write-once media, which use a virtual allocation table, and the Linux driver cannot write those), so the metadata
partition support is only covered by the synthetic images of the PHPUnit suite.

## Manifests

`manifests/<image>.<volume>.sha256` lists the SHA-256 of every regular file of the source tree an image was built
from (sorted by path, `/` separators, symbolic links left out). `<volume>` is the `isotool --volume` value, `default`
meaning no `--volume`; `<image>.boot.sha256` is the hash of the El Torito default boot image. The smoke tests
(`tests/smoke/run.sh`) extract every image and compare the result with these files, so the expectation does not come
from this library. The El Torito catalog (`boot/boot.cat`) is part of `eltorito.iso` but not of its source tree: its
hash comes from `xorriso`'s own extraction.

## Content

`rockridge.iso` (volume id `ROCKRIDGE`)

* `/hello.txt` (17 bytes), `/link_to_hello` symlink to `hello.txt` (size 0)
* `/long_name_` x21 + `.txt` (214 characters, 5 bytes)
* `/dir1/dir2/dir3/dir4/dir5/deep.txt` (5 bytes)

`iso1999.iso` (volume id `ISO1999`)

* `/a_rather_long_file_name_for_level_four.txt` (32 bytes), `/subdir/nested.dat` (7 bytes)
* Volume descriptors: PVD, then an EVD (type 2, version 2, no Joliet escape sequences), then the terminator.

`joliet_cjk.iso` (Joliet volume id `ボリューム中文`; the PVD volume id holds the raw UTF-8 bytes of the same text,
which is not strictly valid ACHARS but is what genisoimage writes)

* `/中文文件.txt` (8 bytes), `/日本語ファイル.txt` (9 bytes)
* `/ディレクトリ/ネスト.txt` (7 bytes)
* The primary tree uses mangled names (`_____000.TXT;1`, ...), the Joliet tree has the real names.

`no_extension.iso` (volume id `NOEXT`)

* `README` (7 bytes), `LICENSE` (13 bytes), `DATA.TXT` (5 bytes); level 1 names are stored as `README.;1`.
* A `;2` version file could not be produced: neither genisoimage nor xorriso can write explicit version numbers.
